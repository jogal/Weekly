# AI受け取り箱（Claude / ChatGPT → Notion → 週クエ）

ClaudeやChatGPTに英語学習のスクショや問題集を送ると、AIが丸つけをしてNotionの「Weekly 受け取り箱」に1行書く。
「〇〇をタスクに追加して」と頼んだときも同じ。週クエは開いたときとアプリに戻ったときに、その行を取り込む。

```
Claude / ChatGPT ──(Notionコネクタ)──▶ Notion「Weekly 受け取り箱」
                                          ▲  読む・取り込み済みの印
週クエ ──(GET ?key=合い言葉)──▶ Google Apps Script（Notionのシークレットはここだけ）
```

記録の正本は今まで通り端末の中。AI経由の記録は手入力と同じ扱いで、おまけのゴールドは付けない。

## 受け取り箱の項目

| 項目 | 型 | 英語 | タスク |
| --- | --- | --- | --- |
| 内容 | タイトル | 教材や内容 | タスク名（40文字まで） |
| 種類 | セレクト | 英語 | タスク |
| 日付 | 日付 | 学習した日（なし・未来なら今日。30日より前は取り込まない） | 期限（なくてもよい） |
| 分 | 数値 | 学習時間 | ― |
| 問題数・正解数 | 数値 | 丸つけの結果 | ― |
| メモ | テキスト | 苦手なところなど | ― |
| ステップ | テキスト | ― | 改行区切り（30個まで。超過時は取り込まず残す） |
| ゴールド | 数値 | ― | 完了時のごほうび（空なら30G、0〜200G） |
| 取り込み済み | チェックボックス | AIは触らない | AIは触らない |

- 英語: 既存の「英語学習」（`wt_records` の `english`）をその日の完了にする。時間は足し算、メモに `🤖 TOEIC Part5 20問中18問正解（90%）` のような1行を足す（手書きのメモは残す）
- タスク: 今日タブの「大きなタスク」に追加（アイコン 📝）。ゴールドは今まで通りステップ5G・完了でごほうび
- 種類が空、数字がないなど読めない行は取り込まず、Notionに残す。直せば次回入る
- 取り込んだ行のIDを端末（`wt_inbox_v1`）が覚えるので、取り込み済みの印付けに失敗しても二重に入らない
- 接続コードは `wt_inbox_v1` にだけ置き、データの書き出しには入れない

ロジックは `js/inbox-core.mjs`、画面と通信は `js/inbox-ui.mjs`。

## セットアップ（初回だけ）

**Notion**

1. 「Weekly 受け取り箱」データベースを上の項目で作る（非公開の場所に）
2. notion.so/profile/integrations で内部インテグレーション「Weekly inbox」を作る。権限は「コンテンツを読み取る」「コンテンツを更新」だけ
3. シークレットを控える（チャットやリポジトリには貼らない）
4. 受け取り箱の … → 接続 → Weekly inbox を追加（このデータベースだけにつなぐ）
5. データベースURLの32文字の英数字がデータベースID

**Google Apps Script**

6. script.google.com で新しいプロジェクトを作り、[ai-inbox-apps-script.gs](ai-inbox-apps-script.gs) を丸ごと貼る
7. プロジェクトの設定 → スクリプト プロパティに `NOTION_TOKEN`・`NOTION_DB_ID`・`WEEKLY_KEY`（20文字以上のランダムな英数字）を入れる
8. エディタで `testList` を実行し、権限を許可。ログに `[]` か行の一覧が出ればOK
9. デプロイ → 新しいデプロイ → ウェブアプリ。実行ユーザー: 自分、アクセス: 全員。`/exec` で終わるURLを控える

**週クエ**

10. 設定 → 🤖 AI受け取り箱 に `/exec のURL|WEEKLY_KEY` を貼って「保存して接続」

アクセスを「全員」にしても、合い言葉が合わない呼び出しには何も返さない。コードを直したら「デプロイを管理」で同じデプロイの新しいバージョンにする（URLが変わらない）。

## 限定的なタスク統合

「タスク統合」は、利用者が承認した複数の未着手タスクを1つの大きなタスクにまとめる操作です。
一般的な削除／パッチ API ではありません。元タスクを **2〜30件、1件ずつ完全指定**した非公開の命令だけを受け付けます。
元タスク1件が統合先の1ステップになります。正本は端末の localStorage です。

公開コードやテストには、実際の利用者のタスク名・作成日・Notion行ID・それらのハッシュを含めません。
実際の対象一覧は利用者の許可を確認してから、既存の非公開受け取り箱の「メモ」に JSON として渡します。
Apps Script は既存の `note` をそのまま中継するため、再デプロイ・認証や権限の変更は不要です。

### 命令の形（以下はすべて架空の例）

- 種類: `タスク統合`
- 内容: 統合先のタスク名（1〜40字）
- 日付・ゴールド: 空欄
- ステップ: 通常は空欄。コネクタの文字数上限でメモに収まらない場合だけ、下記JSONの後半を置きます（通常タスクのステップ名とは別の用途です）
- 取り込み済み: 未チェック。端末が成功後に付けます
- メモ: 下記 JSON。長い場合はメモに前半、ステップに後半を置き、**メモ＋ステップをそのまま連結した文字列が元のJSONと完全一致**するようにします（各欄1800文字以内を目安）。どちらもtrimや改行の追加をしないでください
- 登録時はまず種類を空欄にした1行を作り、保存後に両欄を読み戻して全文一致を確認してから種類を `タスク統合` にします。不一致なら同じ行だけを修復し、別の行を重複作成しません
- 旧版クライアントはステップ欄が空でない統合命令を取り込まず残します。2欄方式は対応版の公開後に有効化してください

```json
{
  "version": 1,
  "operation": "consolidate-tasks",
  "operationId": "example-group-01",
  "sources": [
    {
      "inboxId": "00000000-0000-4000-8000-000000000001",
      "name": "架空の作業A",
      "createdOn": "2001-01-01",
      "steps": ["準備", "作成", "確認"],
      "label": "作業A"
    },
    {
      "inboxId": "00000000-0000-4000-8000-000000000002",
      "name": "架空の作業B",
      "createdOn": "2001-01-01",
      "steps": ["準備", "作成", "確認"],
      "label": "作業B"
    }
  ]
}
```

`operationId` は同じ操作の再送では変えません。8〜64文字の英数字・`_`・`-`、先頭は英数字です。
`inboxId` は元タスクを作った Notion 行ID（端末タスクIDではない）。`name`・`createdOn`・`steps` は元の値を正確に指定します。
`label` が統合先のステップ名です。名前とラベルは40字まで、元ステップは30個までです。
未知のキー、不正な日付、重複した名前／ID／ラベル、欠けた JSON、ワイルドカード、上限超過は受け付けません。

### 安全条件

- 公開版を確認してから命令を追加し、端末の最新データを書き出して保存してください。
- 最新サービスワーカーが、古い版や非表示の画面を含めて**アプリのウィンドウが1つだけ**と確認できる場合のみ実行します。応答なし・非対応の旧版・複数画面・サービスワーカーなしは保留します。編集中のシートも閉じてください。
- 各元タスクの名前が一意で、作成日・アイコン（📝）・期限（なし）・報酬（30G）・元ステップ名／順序が完全一致する場合だけ実行します。
- **1件でも完了・部分進捗・編集・不足・重複があれば統合だけ保留**します。設定画面に理由を表示し、Notionの行は未取り込みのまま残します。進捗を消して強制統合しないでください。
- 指定以外のタスク・日課・習慣・英語・本・報酬の保存先は変更しません。対象外の todo のフィールドも正規化で消さず保持します。
- `wt_task_consolidation_backup_v1` に操作ごとの独立バックアップを先に保存・検証します。同じ操作の既存バックアップは上書きしません。失敗時は統合しません。
- 続いて `wt_todo_v1` の1回の `setItem` で、元タスクの置換と実行済み記録・元データのコピーを同時に保存します。保存後に seen や Notion ACK が失敗しても再実行で重複しません。
- 同じ操作IDに異なる内容が届いたら止まります。統合先を後から編集・削除しても再作成しません。統合済み元タスクの古い編集画面からの保存も拒否します。
- 元 Notion 行IDの再送は、通常の seen キャッシュが期限切れでも実行済み記録と照合して再作成しません。
- localStorage の1書き込みは原子的ですが、複数タブをまたぐ read-modify-write はトランザクションではありません。確認直後に新たな古いタブが現れる競合までは完全保証できないため、作業中も1画面を維持してください。

### バックアップと復旧

既存の書き出し JSON に、次の2つが含まれます。

- `habitData.wt_todo_v1.taskConsolidations[operationId]`: 実行済み記録。`targetInitial` は統合直後のタスク、`sources[].task` は元タスク全文、`sources[].index` は元位置
- `habitData.wt_task_consolidation_backup_v1.operations[operationId]`: 事前コピー。`todoBefore` と同じ形式の `receipt` を保存。**準備の証拠であり、統合完了の証拠ではありません**

これらは端末と書き出したバックアップだけに保存し、Notion/Driveの同期用ミラーには含めません。
復旧時はまず現在のデータを別途書き出し、統合先の後続の編集・完了を確認し、対象タスクだけを戻す個別作業として扱います。
古い全体JSONの復元は後続の別タスク・習慣・読書を失うため行わないでください。実行済み記録を無条件に消す自動ロールバックはありません。

検証: `node --test tests/*.test.mjs`。純粋ロジックとDOM／通信／ストレージモックで、厳密照合・容量エラー・クラッシュ・再送・編集中の保留・複数画面・混在バッチ・バックアップ保持を検査します。
実機では新しい同期ミラーで統合先と対象外データの維持を確認します。ミラーは確認専用で、そこから端末の正本を上書きしません。
