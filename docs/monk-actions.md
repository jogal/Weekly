# Monk companion actions

Gym Questの主人公に「構え→正拳突き→構え」と「構え→力こぶポーズ→構え」を追加。待機にはアクション版を参考に新規生成した呼吸用2コマを使う。

- Lv1/10/20/30/40の全段階で、新規生成した待機用WebP（640×384、横2コマ）を利用。各320×384セルはアクションと同寸法で、Gymでは160×192px表示。足元の基準を合わせる。
- 胸・肩・腕の位置が少し異なる呼気／吸気の絵を0.8秒ずつ表示。CSSは表示するコマを横に切り替えるだけで、拡大縮小はしない。Weeklyのステータス／拡大表示、Workout完了カードも共通。
- 待機画像の取得に失敗したら同レベルのアクション版の構え、それも失敗したら既存idleへフォールバック。既存画像は変更・削除しない。

- 通常は18〜32秒ごとに、正拳突き（0.8秒）と力こぶ（1.76秒）を交互に再生。
- モンクをタップ／キーボード操作でも再生。動作中の連打や短時間の連続再生は抑制。
- 新たに3/4/5種目を達成すると力こぶで反応。画面外で達成した場合は5秒以内に戻ったときのみ再生し、後から古い演出を積み上げない。
- 画面外、別タブ、PWAのバックグラウンドではタイマーとidleを停止。復帰時は待機から再開。
- 入力欄／モーダル操作中は新しいアクションを抑制。
- `prefers-reduced-motion` では待機の1コマ目で静止表示。アクション素材が読めなくても待機2コマは利用できる。
- Lv1/10/20/30/40に対応。idleが下位レベルへフォールバックした場合はアクションもその衣装に合わせる。
- 記録・XP・localStorage・プラン生成の計算は変更なし。アクションは保存データを書き換えない。
- SW v52で表示コードのキャッシュを更新。待機用5枚とアクション用5枚のWebPを事前キャッシュし、オフラインでも利用可能。

## Files

`js/monk-companion.mjs` は表示とライフサイクルのみを担当。Gymの再描画時にはdetachして古いタイマーとIntersectionObserverを破棄する。

[アクション素材の生成プロンプト](monk-action-prompts.md)と[待機2コマの生成プロンプト](monk-idle-prompts.md)。待機用は画像生成ツールで新規作成し、`tools/import_monk_idle.cjs`で切り出し・共通倍率での縮小・足元の整列を行う。元のidle PNGとアクションWebPは変更していない。

## Validation

```sh
node --test tests/*.test.mjs
BROWSER_PATH=<chromium> node tests/gym-ui.cjs
BROWSER_PATH=<chromium> node tests/monk-actions-ui.cjs
```

PlaywrightとChromiumは確認環境のみ。139件のロジックテストと既存Gym回帰、アクション遷移／連打／省アニメーション／背景復帰／画面外／タブ切替／達成時／全レベル／ストレージ不変／素材取得失敗／オフラインを確認。320/375/390/430/1024pxで表示確認。各画像に異なる2枚の絵が含まれること、透過と足元の基準、伸縮せずコマだけを切り替えることを確認。Workout完了カードとWeeklyの通常／拡大表示でも一度に1コマだけが見えることを確認。
実機iPhone・Safariは未確認。
